# P-KC-05 — Sincronizare imediată a utilizatorilor modificați în Active Directory

| Metadate | Valoare |
|---|---|
| Serviciu | Keycloak — Identity & SSO |
| Încadrare | 05 — Proceduri / Runbooks |
| Scop | Actualizarea imediată în Keycloak a utilizatorilor modificați sau redenumiți în Active Directory, fără a aștepta sincronizarea programată |
| Versiune de referință | Keycloak 26.6.2, instalat nativ în `/opt/keycloak` |
| Realm Keycloak | `AD` |
| Integrare | LDAP Federation `READ_ONLY`, `Import Users = ON`, Kerberos/SPNEGO |
| Revizie | 1.0 — 16.11.2026 |
| Impact | Sincronizarea actualizează datele utilizatorilor importați; golirea cache-ului nu este un logout, dar poate crește temporar numărul de accesări LDAP/DB |
| Clasificare | Intern — administrare IT |

## 1. Scop și situații de utilizare

Această procedură se utilizează când în Active Directory au fost schimbate date precum `displayName`, `givenName`, `sn`, `sAMAccountName`, `userPrincipalName` sau `mail`, iar în Keycloak sunt încă vizibile valorile anterioare. În mediul curent, sincronizarea LDAP programată se execută periodic, astfel că modificările pot apărea cu întârziere.

**Distincție obligatorie:**

- **LDAP Changed Users Sync**: solicită providerului LDAP să importe/actualizeze în Keycloak utilizatorii pe care îi consideră modificați **după ultima sincronizare**. Nu este o sincronizare a unui singur utilizator, ci a providerului LDAP.
- **`clear-user-cache`**: invalidează cache-ul utilizatorilor din realm; **nu actualizează singur datele deja persistate greșit în baza Keycloak**.
- **LDAP Full Sync**: procesează toți utilizatorii din domeniul de căutare al providerului; este o operație mai costisitoare, folosită numai dacă sincronizarea incrementală nu preia schimbarea.

## 2. Condiții preliminare

1. Confirmați că valorile actualizate apar în Active Directory și, ideal, pe Domain Controller-ul la care se conectează Keycloak.
2. Aveți acces la `kcadm.sh` și drepturi administrative asupra realm-ului `AD`.
3. Confirmați că providerul LDAP vizat are `Import Users = ON`. În modul fără import, mecanismul de persistență și sincronizare diferă.
4. Nu efectuați concomitent schimbări ale mapperelor LDAP sau update-uri SQL manuale.
5. Pentru **Full Sync**, verificați un backup recuperabil al bazei **externe** Keycloak; snapshotul VM-ului SSO nu acoperă baza externă.

## 3. Procedura standard — Changed Users Sync + clear-user-cache

### Pasul 1 — Autentificarea în Keycloak Admin CLI

Conform [P-KC-01 — Autentificare cu kcadm.sh](./01-Logare-CLI-kcadm.md):

```bash
/opt/keycloak/bin/kcadm.sh config credentials \
  --server https://sso.exemplu.ro \
  --realm master \
  --user admin
```

Înlocuiți URL-ul și utilizatorul administrativ cu cele reale. Parola se introduce interactiv; **nu se scrie în comandă sau în Outline**.

### Pasul 2 — Identificarea ID-ului providerului LDAP

```bash
/opt/keycloak/bin/kcadm.sh get components -r AD \
  -q type=org.keycloak.storage.UserStorageProvider | \
  jq -r '.[] | select(.providerId == "ldap") | [.id, .name] | @tsv'
```

Dacă există mai mulți provideri LDAP, selectați ID-ul celui care conține utilizatorul vizat. ID-ul este UUID-ul componentei, **nu** numele afișat în interfață.

```bash
LDAP_ID="UUID_REAL_AL_PROVIDERULUI_LDAP"
echo "LDAP_ID=[$LDAP_ID]"
```

### Pasul 3 — Notarea valorilor înainte de sincronizare (recomandat)

Pentru un utilizator identificat după numele curent/vechi:

```bash
/opt/keycloak/bin/kcadm.sh get users -r AD \
  -q username="username_utilizator" \
  -q exact=true | \
  jq '.[] | {id,username,firstName,lastName,email,enabled}'
```

Dacă utilizatorul a fost redenumit, căutați și după numele vechi. Când este cunoscut, **ID-ul intern al utilizatorului** este o referință mai stabilă decât username-ul:

```bash
/opt/keycloak/bin/kcadm.sh get users/UUID_UTILIZATOR -r AD | \
  jq '{id,username,firstName,lastName,email,enabled,attributes}'
```

### Pasul 4 — Declanșarea sincronizării incrementale LDAP

```bash
/opt/keycloak/bin/kcadm.sh create \
  "user-storage/$LDAP_ID/sync?action=triggerChangedUsersSync" \
  -r AD
```

**Rezultat așteptat:** răspuns de sincronizare fără eroare. Examinați indicatorii de succes/actualizare/eșec returnați de server. Un rezultat fără utilizatori actualizați nu garantează că noua valoare a fost preluată: poate să nu se mai încadreze în fereastra de modificări urmărită de provider.

### Pasul 5 — Invalidarea cache-ului utilizatorilor

Conform [P-KC-02 — Golirea cache-ului](./02-Stergere-cache-utilizatori.md):

```bash
/opt/keycloak/bin/kcadm.sh create clear-user-cache \
  -r AD -s realm=AD
```

Comanda nu șterge utilizatorii, **nu închide sesiunile SSO** și nu revocă tokenurile deja emise. Invalidează cache-ul de utilizatori al realm-ului `AD`; în cazul unui trafic ridicat poate crește temporar accesul la LDAP și baza Keycloak.

### Pasul 6 — Verificarea rezultatului

```bash
/opt/keycloak/bin/kcadm.sh get users/UUID_UTILIZATOR -r AD | \
  jq '{id,username,firstName,lastName,email,enabled,attributes}'
```

Comparați cu datele AD, de exemplu pe un sistem Windows cu modulul Active Directory:

```powershell
Get-ADUser -Identity "username_utilizator" -Properties userPrincipalName,displayName,mail,whenChanged |
  Select-Object SamAccountName,UserPrincipalName,DisplayName,Mail,WhenChanged |
  Format-List
```

Dacă se folosește alt DC decât cel interogat implicit în PowerShell, adăugați `-Server "dc01.exemplu.ro"` la `Get-ADUser`.

Pentru `KERBEROS_PRINCIPAL`, comparați cu `userPrincipalName` **real** din AD și consultați [P-KC-04 — Diferențele de capitalizare](./04-Kerberos-majuscule-minuscule.md). Sufixul `STS.NEST` poate fi afișat cu majuscule în context Kerberos, fără să indice o redenumire greșită.

## 4. Dacă Changed Users Sync nu actualizează utilizatorul

1. Verificați că modificarea există pe **DC-ul folosit de Keycloak**, nu doar pe alt DC.
2. Verificați configurația mapperelor `username`, `first name`, `last name`, `email` sau `kerberos-principal-attribute-mapper`, după atributul afectat. Consultați [P-KC-03 — Mapper Kerberos LDAP](./03-Mapper-Kerberos-LDAP.md).
3. Dacă utilizatorul este în afara ferestrei incrementale sau rezultatul rămâne neactualizat, executați **Full Sync** doar după verificarea backupului bazei externe și evaluarea impactului asupra întregului provider:

```bash
/opt/keycloak/bin/kcadm.sh create \
  "user-storage/$LDAP_ID/sync?action=triggerFullSync" \
  -r AD

/opt/keycloak/bin/kcadm.sh create clear-user-cache \
  -r AD -s realm=AD
```

**Nu este necesar să executați Full Sync după fiecare redenumire.** Este un pas de escaladare, nu procedura de rutină. Dacă nici Full Sync nu actualizează datele, investigați maparea atributului, filtrul LDAP, identificatorul obiectului AD și logurile Keycloak; nu repetați operațiile fără diagnostic.

## 5. Impact asupra sesiunilor și aplicațiilor SSO

| Componentă | Changed Sync / clear-user-cache |
|---|---|
| Date locale importate în Keycloak | Pot fi actualizate de LDAP Sync |
| Cache utilizatori | Este invalidat de `clear-user-cache` |
| Conturi din AD | Nu sunt modificate (provider `READ_ONLY`) |
| Sesiuni SSO Keycloak deja active | Nu sunt terminate de aceste comenzi |
| Access token / ID token deja emis | Nu este rescris sau revocat automat |
| Aplicații precum Grafana/Huly | Pot păstra numele vechi în sesiunea sau baza lor până la reautentificare / resincronizarea profilului |

**Important:** dacă verificarea în Keycloak arată numele nou, dar aplicația încă îl afișează pe cel vechi, problema se poate afla în tokenul deja emis sau în profilul păstrat local de client. Nu executați **Sign out all sessions** doar pentru o modificare de nume. Dacă este necesar, testați reautentificarea **numai a utilizatorului vizat**, după analiza efectului asupra sesiunii sale.

## 6. Diagnostic rapid

| Situație | Verificare / acțiune |
|---|---|
| `no server specified` | Refaceți logarea conform [P-KC-01](./01-Logare-CLI-kcadm.md) |
| `401 Unauthorized` | Reautentificați `kcadm.sh` |
| `403 Forbidden` | Verificați drepturile administratorului în realm-ul `AD` |
| ID LDAP greșit / rezultat gol | Listați providerii și verificați `echo "$LDAP_ID"` |
| Changed Sync raportează 0 schimbări | Verificați timestampul ultimei sincronizări și condițiile incrementalului; evaluați Full Sync dacă este justificat |
| AD corect, Keycloak încă vechi | Verificați mapperele, DC-ul folosit, logurile și importul utilizatorilor |
| Keycloak corect, aplicația afișează vechiul nume | Verificați sesiunea/tokenurile și stocarea locală a aplicației |

## 7. Checklist de închidere

- [ ] Datele din AD sunt corecte pe DC-ul interogat de Keycloak.
- [ ] A fost selectat UUID-ul corect al providerului LDAP.
- [ ] `triggerChangedUsersSync` s-a încheiat fără eroare.
- [ ] A fost executat `clear-user-cache` pentru realm-ul `AD`.
- [ ] Utilizatorul vizat afișează valorile actualizate în Keycloak.
- [ ] Sesiunile SSO existente nu au fost revocate.
- [ ] Dacă a fost necesar Full Sync, rezultatul și aprobarea au fost consemnate în Change/Incident.
